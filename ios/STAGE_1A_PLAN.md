# iOS — План етапу 1a «Демо-режим лише для перегляду»

> **Статус:** виконано.

Етап 1a з `docs/functional-design.md` (розділ 6): AUTH-10 · Q-08. Залежить від етапу 1; має бути готовий до етапу 2 —
першої дії, що змінює дані.

Результат для користувача: «Спробувати демо-режим» миттєво відкриває застосунок із готовими демо-даними, без
мережі й без акаунта; дії, що змінюють дані, нічого не змінюють; «Вийти» повертає на екран входу.

## Стан на початку етапу

- Кнопка «Спробувати демо-режим» входить у **спільний серверний акаунт** `demo@mail.com`
  (`SupabaseAuthRepository.signInWithDemo`). Будь-який запис у демо змінював би дані для всіх демо-користувачів.
- Налаштування в меню профілю доступні й у демо.

## Рішення

- **Як на web** (`src/app/core/services/demo-mode/`): окрема реалізація доступу до даних із локальними демо-даними;
  кожен запис — no-op. На відміну від web, iOS **не входить** у серверний демо-акаунт: сесії Supabase в демо немає
  взагалі, мережа не потрібна (`Q-08`).
- Демо-дані — ті самі, що на web (`demo-data.ts`): рахунки Main Card (USD), Cash (UAH), Savings (EUR); групи
  Food, Transport, Entertainment, Housing (витрати) і Salary (дохід) з категоріями; валюти USD, UAH, EUR.
- Прапорець демо-режиму зберігається на пристрої: після перезапуску користувач лишається в демо, як і з
  звичайною сесією (`AUTH-12`). «Вийти» вимикає демо й очищає налаштування (`AUTH-11`).
- Репозиторії обираються в одному місці — контейнер `Repositories` з наборами `live` і `demo`;
  `AppViewModel.repositories` віддає потрібний. Кожен наступний етап додає свої репозиторії в обидва набори.

## Кроки

### 1. Демо-дані й демо-репозиторії

- [x] `Core/Demo/DemoData` — статичні демо-дані (рахунки, групи, категорії, валюти), як у web.
- [x] `Core/Demo/DemoReferenceDataRepository` — реалізує `AccountsRepository`, `CategoriesRepository`,
      `CurrenciesRepository` на `DemoData`. Жодних звернень до мережі.
- [x] Правило для наступних етапів (записати в `ios/CLAUDE.md`): кожен метод запису в демо-реалізації — no-op,
      який завершується успіхом і не змінює даних.

### 2. Вибір репозиторіїв

- [x] `Core/Repositories` — контейнер `Repositories` (`accounts`, `categories`, `currencies`) з фабриками
      `live(client:)` і `demo`.
- [x] `ReferenceDataStore.load(using:)` отримує набір репозиторіїв замість того, щоб тримати їх з init.

### 3. Стан демо-режиму

- [x] `Core/Demo/DemoModeStorage` — прапорець у `UserDefaults` (окремо від `DevicePreferences`).
- [x] `AppViewModel`: `isDemo`, `enterDemo()`, `repositories`. При запуску з увімкненим прапорцем — одразу демо.
      Події сесії Supabase ігноруються, поки демо увімкнено.
- [x] `signOut()` у демо: вимкнути прапорець, очистити налаштування й довідкові дані, показати вхід — без
      звернення до сервера.

### 4. Вхід у демо

- [x] `AuthRepository.signInWithDemo` і демо-облікові дані прибрати з `SupabaseAuthRepository`.
- [x] `LoginViewModel.signInWithDemo()` викликає переданий `enterDemo` (з `AppViewModel`), а не репозиторій.

### 5. Обмеження в демо (`AUTH-10`)

- [x] Меню профілю в демо: замість email — «Демо-режим», пункт «Налаштування» прихований.

### 6. Тексти й тести

- [x] Рядок `profile.demoMode` (en / uk / cs).
- [x] Тести: вхід у демо без виклику auth-репозиторію; маршрут `main` з демо-даними; основна валюта — USD;
      перезапуск із прапорцем відкриває демо; події сесії не виводять із демо; вихід із демо не викликає сервер і
      вимикає прапорець; демо-репозиторій не повертає службових записів.
