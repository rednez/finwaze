# iOS — План етапу 4 «Редагування, видалення, мультивалютність»

> **Статус:** виконано.

Етап 4 з `docs/functional-design.md` (розділ 6): TX-22, TX-40…42, а також те, що етап 3 лишив на потім: TX-06
(відкриття операції), повний TX-21 (вибір валюти покупки) і GEN-22 (підтвердження видалення). Залежить від етапу 3.

Результат для користувача: можна виправити чи видалити операцію та записати покупку в іноземній валюті.

## Рішення

- **Схеми Supabase не змінюються.** Усе будується на тому, що вже використовує web:
  - деталі операції — `select` з `transactions` за `id` з вкладеними `accounts`, `currencies` (операції й
    списання), `categories` → `groups`, як `getTransactionDetails` на web; до вибірки додаємо `color` групи й
    категорії (лише ширший `select`, схема та сама);
  - збереження — `update` за `id` з `select("id")` у відповідь: порожня відповідь означає, що операції вже немає
    (видалено деінде або RLS) → стан «не знайдено» (`TX-42`);
  - видалення — `delete` за `id`, як на web.

  Знак суми витрати ставить тригер `normalize_expense_amounts_trigger` і на `UPDATE`; валюту списання після зміни
  рахунку — `update_charged_currency_trigger`. Обмеження `transactions_amount_currency_check` (однакові валюти →
  однакові суми, різні → різні) збігається з валідацією форми, тож сервер її лише підстраховує.
- **Відкриття операції (`TX-06`)** — перехід у стеку навігації вкладки, а не sheet: це окремий екран із власними
  діями «Зберегти» й «Видалити». `SectionView` переходить з `[AppSection]` на `NavigationPath`, щоб у стек можна
  було класти і розділи з меню «…», і операції. Переказ поки не відкривається: деталі переказу — етап 5 (`TRF-07`).
- **Свіжі дані при відкритті.** Екран редагування завантажує операцію за `id` з сервера, а не бере рядок зі
  списку: так видно зміни з інших пристроїв, а видалену операцію — одразу як «не знайдено» (`TX-42`). Поки
  завантажується — індикатор (`GEN-23`).
- **Час операції при редагуванні.** `DatePicker` показує й змінює дату в **збереженому** `local_offset` операції
  (`.environment(\.timeZone, …)`), і цей самий `local_offset` іде в `update`. Так покупка, зроблена в Києві,
  лишається о тій самій годині за київським часом, навіть якщо редагувати її з Праги (`GEN-12`). Для нової
  операції — як і було: пояс пристрою на момент операції.
- **Одна форма для створення й редагування (`TX-40`).** `TransactionFormViewModel` отримує режим `create` /
  `edit(Transaction)`. У редагуванні: немає перемикача Витрата/Дохід, суми показуються додатними, запам'ятовування
  вибору (`TX-16`) не застосовується й не оновлюється — воно стосується лише нових операцій.
- **Валюта покупки (`TX-21`, `TX-22`)** — тепер вибирається для витрати зі списку валют рахунків (`GEN-11`); за
  замовчуванням і після зміни рахунку — валюта рахунку. Якщо вона відрізняється від валюти рахунку, з'являється
  «Списано з рахунку» у валюті рахунку: обов'язкове, > 0, ≤ 2 знаків, не дорівнює сумі витрати. Коли поле
  з'являється через дію користувача — воно порожнє; при відкритті на редагування іноземної покупки — заповнене
  збереженою сумою списання. Помилка рівності показується під обома полями («Не має дорівнювати сумі списання» /
  «…сумі витрати»). Для доходу валюти не вибирають (`TX-30`).
- **Курс (`GEN-10`)** рахується в `Decimal` (списання ÷ сума операції) і показується під полем як
  `1 EUR = 43,1250 UAH` — від 2 до 4 знаків після коми, як на web, за правилами мови інтерфейсу.
- **Після збереження (`TX-41`)** користувач лишається на екрані й бачить коротке повідомлення «Транзакцію оновлено»
  (невеликий банер у стилі Liquid Glass, що сам зникає; VoiceOver його озвучує). Дані оновлюються через
  `AppViewModel.dataVersion` (`GEN-26`) — список і Гаманець перечитаються.
- **Видалення (`TX-41`, `GEN-22`, `Q-01`)** — лише з підтвердженням (`confirmationDialog` з руйнівною дією). Після
  успіху — назад до списку й `dataChanged()`. Помилка — «Не вдалося видалити транзакцію» з поясненням сервера.
  Видалення вже видаленої операції вважаємо успіхом (результат для користувача той самий).
- **Демо.** `DemoTransactionsRepository` знаходить операцію за `id` у згенерованих даних (з `id` видно місяць:
  `YYYYMM·100 + n`); `update` і `delete` — no-op, тож демо-операція після «збереження» лишається як була, а
  «видалена» — на місці.

## Кроки

### 1. Дані: деталі, оновлення, видалення

- [x] `TransactionDetailsDto` під вкладену вибірку (рахунок, валюти операції й списання, категорія з групою та
      кольорами) і `TransactionMapper.toTransaction(_: TransactionDetailsDto)`.
- [x] `TransactionsRepository`: `transaction(id:) async throws -> Transaction?` (`nil` — не знайдено),
      `update(id:_:) async throws -> Bool` (`false` — не знайдено), `delete(id:) async throws`.
- [x] `TransactionUpdate` (рахунок, категорія, суми, валюта операції, дата, `local_offset`, коментар — без типу) і
      `TransactionUpdateDto`.
- [x] `SupabaseTransactionsRepository` — як на web; `DemoTransactionsRepository` — пошук за `id`, запис no-op.
- [x] `FakeTransactionsRepository` у тестах: деталі, оновлення, видалення, «не знайдено».
- [x] Тести мапера деталей (вкладені об'єкти, `NUMERIC` → `Decimal`, від'ємна витрата) і демо-пошуку за `id`.

### 2. Валюта покупки й сума списання (`TX-21…23`, `GEN-10`)

- [x] `TransactionFormViewModel`: `purchaseCurrencyCode` — стан, а не похідне від рахунку; список валют рахунків;
      зміна рахунку скидає валюту на валюту рахунку; `chargedAmountText` + `showsChargedAmount`; поле очищується,
      коли з'являється через зміну валюти чи рахунку.
- [x] Валідація списання: обов'язкове, > 0, ≤ 2 знаків, ≠ сумі витрати — з помилкою під обома полями.
- [x] `exchangeRate` (`Decimal`) і текст підказки; `Decimal` форматування курсу 2…4 знаки.
- [x] Запам'ятована валюта покупки (`TX-16`): застосовується після рахунку, якщо вона серед валют рахунків.
- [x] `NewTransaction`: `transactionCurrencyID` — валюта покупки, `chargedAmount` — списання або сума.
- [x] UI: у полі суми — вибір валюти (`Menu`), поле «Списано з рахунку» з підказкою курсу; анімація появи.
- [x] Тести: скидання валюти при зміні рахунку, поява/очищення поля, усі помилки списання, курс
      (`215 / 5 = 43`), запит з різними сумами й валютою покупки, запам'ятована валюта.

### 3. Режим редагування форми (`TX-40`)

- [x] `TransactionFormViewModel.Mode` (`create` / `edit`): заповнення з `Transaction` (абсолютні суми, валюта
      покупки, списання для іноземної покупки, дата, коментар), тип зафіксовано, без `TX-16`.
- [x] `local_offset` у редагуванні — збережений; `DatePicker` у його часовому поясі.
- [x] `submit()` у редагуванні → `update`; результат `saved` / `notFound` / `failed`.
- [x] Тести: заповнення витрати в гривні, іноземної покупки й доходу; незмінність `local_offset`; `update` з
      додатними сумами; `notFound`; помилка зберігає дані; запам'ятований вибір не змінюється.

### 4. Екран редагування (`TX-41`, `TX-42`, `GEN-22`)

- [x] `EditTransactionViewModel`: завантаження за `id` (`loading` / `loaded` / `notFound` / `failed`), збереження з
      банером «Транзакцію оновлено», видалення з підтвердженням, `dataChanged()` після змін.
- [x] `EditTransactionView`: та сама форма без перемикача типу, «Зберегти зміни» і «Видалити» (руйнівна,
      `confirmationDialog`), «Назад» без збереження (`NAV-05`).
- [x] Стан «не знайдено»: пояснення й «До списку транзакцій»; той самий стан, якщо операцію видалили, поки екран
      був відкритий (виявлено під час збереження).
- [x] Спільний `SuccessBanner` у `Shared/Views` (з'являється зверху, зникає за ~2 с, `AccessibilityNotification`).
- [x] Тести ViewModel: стани завантаження, успішне збереження (банер, `dataVersion`), видалення (підтвердження,
      повернення), `notFound` при відкритті й при збереженні, помилки.

### 5. Відкриття операції зі списку (`TX-06`)

- [x] `SectionView`: `NavigationPath`; `navigationDestination` для розділів і для `TransactionRoute(id:)`.
- [x] `TransactionRow` для витрати й доходу — `NavigationLink(value:)` з шевроном-підказкою; переказ поки без дії
      (етап 5).
- [x] Повернення після видалення — зняти екран зі стеку; список оновлюється через `dataVersion`.

### 6. Локалізація

### 7. Перевірка й документація

- [x] Критерії приймання TX у симуляторі на локальному Supabase:
  - витрата 5 € з рахунку в гривні вимагає «Списано з рахунку» 215 ₴, показує курс 43,00, у списку видно обидві
    суми, баланс зменшився на 215 ₴;
  - однакові суми покупки й списання в різних валютах — помилка під обома полями;
  - зміна рахунку скидає валюту покупки, поле списання зникає; повернення іноземної валюти — поле порожнє;
  - редагування: без перемикача типу, суми додатні, «Транзакцію оновлено», користувач лишається на екрані;
  - видалення з підтвердженням → список без операції, баланс відновився;
  - операція, видалена на web, відкривається як «не знайдено»; збереження вже видаленої — теж «не знайдено»;
  - операція, створена в іншому часовому поясі, після редагування лишається о тій самій місцевій годині;
  - у демо: відкриття, збереження й видалення нічого не змінюють.
- [x] Dark Mode, Dynamic Type, VoiceOver на формі з валютою й списанням і на екрані редагування.
- [x] `ios/docs/TECH_DEBT.md`: прибрати з «Transactions are partial» редагування, видалення й валюту; лишити деталі
      переказу (етап 5).
