# iOS — План етапу 10 «Бюджет: планування»

> **Статус:** виконано.

## Контекст

Етап 10 з `docs/functional-design.md` (розділ 6): **BUD-20…26**. Залежить від етапу 9: екран «Бюджет» уже показує план
місяця, а дії «Додати бюджет», «Редагувати бюджет» і «Створити бюджет» відкривають заглушку `BudgetPlanPlaceholder`
(`ios/docs/TECH_DEBT.md`). Результат для користувача: створити план місяця у вибраній валюті — згенерувати з минулого
місяця або скласти вручну, — змінити його й зберегти.

## Рішення

- **Схеми Supabase не змінюються.** Беремо ті самі RPC, що web (`create-budget-store.ts`, `budget-repository.ts`), з
  `supabase/schemas/monthly_budgets_funcs.sql`, `p_month` — `"YYYY-MM-01"` (`YearMonth.firstDayParameter`):
  - `get_monthly_budgets_detailed(p_month, p_currency_code)` — план місяця по категоріях з групами й довідковими
    цифрами: план і витрати минулого місяця, витрати цього (`BUD-20`, `BUD-22`). Сервер повертає й незаплановані
    категорії (`planned_amount = 0`); як web, у план беремо лише ті, що мають суму > 0;
  - `generate_monthly_budgets_from_previous(p_month, p_currency_code)` — пропозиція за пріоритетом із `BUD-21`
    (бюджет минулого місяця → витрати минулого → витрати цього); нульові сервер уже відкидає. Нічого не зберігає;
  - `get_category_budget_stats(p_month, p_currency_code, p_category_id)` — довідкові цифри категорії, доданої вручну
    (`BUD-24`);
  - `upsert_monthly_budgets(p_month, p_currency_code, p_categories)` — замінює план місяця й валюти повністю: нові
    категорії додає, змінені оновлює, відсутні в списку видаляє (`BUD-26`). `p_categories` — JSON-масив
    `[{ "category_id": 1, "planned_amount": 250.5 }]`.
  Усі суми з цих функцій уже додатні; мапер однаково бере модуль і `null` → 0, як на етапі 9.
- **Де живе код.** Той самий `Features/Budget`: до `BudgetRepository` додаються `plan(month:currencyCode:)`,
  `generatedPlan(month:currencyCode:)`, `categoryStats(month:currencyCode:categoryID:)`,
  `savePlan(month:currencyCode:amounts:)`; нові моделі `BudgetPlanLine` (категорія, група, план, план минулого,
  витрачено, витрачено минулого) і `BudgetPlanStats`; DTO `MonthlyBudgetDetailedDto` (один на `…_detailed` і
  `generate_…` — рядок однаковий) і `CategoryBudgetStatsDto`. Редактор — `BudgetPlanDraft` (чиста структура зі всією
  логікою плану), `BudgetPlanViewModel`, `BudgetPlanView` + рядки. `BudgetPlanPlaceholder` видаляється.
- **Чернетка плану — `BudgetPlanDraft`.** Чиста `Sendable`-структура, щоб усю логіку `BUD-22…26` покрити тестами без UI:
  - групи в порядку, як прийшли з сервера (найбільший план першим), додані — в кінці; у групі — категорії, кожна з
    текстом суми, як його ввів користувач, і довідковими цифрами (`BudgetPlanStats?` — `nil`, поки вантажаться або
    якщо не вдалося, тоді в рядку «—», а не 0);
  - підсумки групи й усього плану за чотирма колонками (`BUD-22`); сума плану рахує лише коректно введені суми;
  - `isDirty` — порівняння «категорія → сума» з останнім збереженим станом (порядок і згорнуті групи не рахуються; текст,
    який не розбирається, — зміна) (`BUD-26`);
  - перевірка кожної суми через `PositiveAmountInput`: порожньо / 0 / від'ємне → «Сума має бути більшою за 0», більше
    двох знаків — наявне повідомлення форм (`BUD-25`, `GEN-07`);
  - `payload` — список «категорія → сума» для збереження; група без жодної категорії просто не потрапляє в план (як web).
- **Відкриття редактора (`BUD-20`).** Sheet на весь екран (`.large`, як «Нова операція»), для місяця й валюти з
  `BudgetFilter` — заголовок «Бюджет на вересень 2026» і підзаголовок з валютою. Відкривається з «Додати бюджет» /
  «Редагувати бюджет» і з порожніх станів «Створити бюджет» на екрані «Бюджет» і на екрані групи (тоді теж план
  усього місяця — план задається на місяць, а не на групу). Спершу — `plan(…)`: є категорії з сумою > 0 → одразу
  редактор; немає → порожній стан `BUD-21`; помилка → «Щось пішло не так» + «Спробувати ще раз» (`GEN-25`; web
  тут просто лишає спінер).
- **Порожній стан (`BUD-21`).** «Немає бюджету на вересень у UAH», пояснення з web (`canGenerate`) і дві дії:
  - **«Згенерувати»** — `generatedPlan(…)`, кнопка з індикатором (`GEN-20`). Результат — чернетка, ще не збережена:
    `isDirty = true`, «Зберегти» активна. Якщо пропозиція порожня (ні бюджету, ні витрат за два місяці) — коротке
    повідомлення «Немає даних, з яких згенерувати бюджет» і лишаємось на порожньому стані (web показує порожню таблицю);
  - **«Створити вручну»** — порожня чернетка, одразу відкрито «Додати групу».
- **Редактор (`BUD-22`).** Таблиця з чотирма числовими колонками на телефоні не влазить, тож:
  - `List` із секцією на групу. Заголовок секції — назва групи, її план разом і кнопка згортання (`DisclosureGroup`);
    «Згорнути все / Розгорнути все» — у меню «…» тулбара;
  - **рядок категорії** на телефоні — два рядки: назва й поле «План» (`TextField`, `.decimalPad`, валюта поруч,
    `GEN-06`); під ними дрібним — «Мин. місяць: план 4 000 ₴ · витрачено 3 800 ₴ · цей місяць: 1 200 ₴». На широкому
    екрані (`horizontalSizeClass == .regular`) — одна лінія з чотирма колонками, як web (`Grid`);
  - під категоріями групи — підсумок групи за чотирма колонками, внизу списку — секція «Разом» для всього плану;
  - назви груп і категорій беремо з `ReferenceDataStore` за id (актуальні після перейменування), з запасною назвою з рядка
    сервера.
- **Додавання й видалення (`BUD-23`, `BUD-24`).**
  - «Додати групу» — sheet зі списком груп **витрат** з `ReferenceDataStore`, яких ще немає в плані, з пошуком
    (`GEN-05`: службових там немає). Нова група — в кінці, розгорнута, і одразу пропонує «Додати категорію»;
  - «Додати категорію» в секції — sheet із категоріями цієї групи, яких ще немає в плані, з пошуком. Рядок з'являється
    одразу з порожньою сумою й фокусом на полі, а `categoryStats(…)` підтягує довідкові цифри у фоні;
  - видалення категорії — свайп або контекстне меню; групи — у меню заголовка секції. Підтвердження немає: це зміна
    чернетки, її скасовує «Закрити» без збереження (`GEN-22` стосується незворотних дій — ним є лише збереження, див.
    нижче);
  - у групі без категорій — підказка «Додайте категорію»; група без категорій не зберігається.
- **Збереження (`BUD-25`, `BUD-26`, `GEN-19…22`).**
  - «Зберегти» в тулбарі активна лише коли `isDirty`; поки зберігає — індикатор і повторне натискання ігнорується;
  - натискання з помилками — помилки показуються під полями, фокус на першому некоректному, запиту немає (`GEN-21`);
  - якщо в збереженому плані були категорії, а тепер план порожній, — підтвердження «Видалити бюджет на вересень
    повністю?», бо збереження видалить план місяця (`GEN-22`; web зберігає без питань);
  - успіх — банер «Бюджет збережено» (`SuccessBanner`), чернетка стає новим збереженим станом, редактор лишається
    відкритим (як web). `AppViewModel.budgetSaved()` піднімає `dataVersion`, тож «Бюджет» і картка бюджету на дашборді
    перечитуються (`GEN-26`);
  - помилка — `failureAlert` «Не вдалося зберегти бюджет» з поясненням сервера, введене не втрачається (`GEN-19`).
- **Закриття (`NAV-05`).** «Закрити» без змін — одразу; зі змінами — `confirmationDialog` «Скасувати зміни?»;
  свайп вниз при змінах вимкнено (`interactiveDismissDisabled`).
- **Демо (`AUTH-10`).** `DemoBudgetRepository` отримує нові методи на тих самих даних:
  - `plan` — `DemoData.plannedBudgets` для місяців до поточного з довідковими цифрами з демо-операцій;
  - `generatedPlan` — той самий пріоритет, що на сервері (план минулого → витрати минулого → витрати цього);
  - `categoryStats` — з демо-операцій;
  - `savePlan` — no-op, що завершується успіхом: банер з'являється, а після перезапуску план той самий.

### 2. Чернетка й ViewModel (`BUD-20…26`)

      групи (лише витрати, без наявних) і категорії, підсумки групи й плану, `isDirty`, перевірка сум, `payload`.
- [x] `BudgetPlanViewModel`: стани `loading` / `failed` / `empty` / `editing`; `generate()`, `startManually()`,
      довантаження статистики доданої категорії, `save()` з `isSaving` і `saveFailure`, підтвердження порожнього плану,
      `hasUnsavedChanges` для закриття.
- [x] Тести: наявний план відкривається одразу; без плану — порожній стан; генерація дає незбережену чернетку й
      активну «Зберегти»; порожня генерація лишає порожній стан; додана категорія отримує статистику, а помилка
      статистики лишає «—»; сума 0 / порожня / три знаки блокує збереження; зміна й повернення суми — не `isDirty`;
      збереження надсилає повний план і скидає `isDirty`; порожній план після наявного вимагає підтвердження; помилка
      збереження лишає чернетку.

### 5. Перевірка й документація
- [x] Збірка й тести: `xcodebuild … -scheme Finwaze -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test`.
- [ ] Критерії приймання BUD у симуляторі на локальному Supabase:
  - «Згенерувати» для нового місяця підставляє суми бюджету минулого місяця; після «Зберегти» вони з'являються на
    екрані «Бюджет»;
  - видалення категорії з плану й збереження прибирає її з бюджету місяця;
  - «Створити вручну»: група + категорія + сума → збережено, видно на «Бюджеті» й у картці бюджету дашборда;
  - сума 0 або порожня не дає зберегти й показує помилку під полем;
  - «Зберегти» неактивна без змін; закриття зі змінами питає підтвердження;
  - повне очищення плану й збереження питає підтвердження і видаляє план місяця;
  - демо: генерація й збереження працюють, але план після перезапуску той самий.
- [ ] Dark Mode, Dynamic Type (найбільші розміри — рядок категорії переходить у кілька рядків), VoiceOver, iPad
      (чотири колонки).
- [x] `ios/docs/TECH_DEBT.md`: прибрати «Budget plan is view-only». Пункт «A category with a planned budget cannot be
      deleted» тепер трапляється частіше — лишити й згадати, що етап 10 створює такі бюджети.
